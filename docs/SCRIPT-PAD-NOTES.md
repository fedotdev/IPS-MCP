# Заметки: ошибка Script Pad и определение версии IPS

Документ фиксирует разбор двух задач: почему падает сценарий в Script Pad и
как надёжно определять версию сервера IPS через Web API (и через MCP-мост).

## 1. Ошибка при выполнении "Новый сценарий C#"

```
Script pad: при выполнении сценария 'Новый сценарий C#' произошло
необработанное исключение
Несоответствие числа параметров.
Тип: System.Reflection.TargetParameterCountException
Стек:
  Intermech.Scripting.CSharp.DesignTime.CSharpSession.DoExecute(String scriptCode, ScriptDebugInvocationParameters invocationParameters)
  Intermech.Scripting.Projects.DiskScripts.DiskScriptDebugBehavior.Execute(...)
  Intermech.Scripting.Threading.StoppableTask.WorkerRoutine(Object state)
```

### Причина

`TargetParameterCountException` из `System.Reflection` означает, что хост
вызвал метод сценария с одним числом параметров, а метод объявлен с другим.
Это не ошибка логики скрипта — исключение возникает **до** выполнения тела,
на этапе рефлективного вызова точки входа.

Конкретный скрипт: `D:\IPS\Scripts\СозданиеПорученияТД.cs`, точка входа —
`public void Execute(IActivity activity)` (строка 40). Это **действие
бизнес-процесса** (IPS Workflow, "Действие \"Сценарий\""), а не сценарий
Script Pad.

`CSharpSession.DoExecute` в клиентском Script Pad передаёт свой набор
аргументов (`ScriptDebugInvocationParameters`), который не совпадает с
сигнатурой `Execute(IActivity)`. Движок бизнес-процесса передаёт объект
`IActivity`, а Script Pad — нет; отсюда несоответствие числа параметров.

### Вывод

- Скрипт `СозданиеПорученияТД.cs` корректно работает **только в контексте
  бизнес-процесса**, где хост сам подставляет `IActivity`.
- Запускать его из **клиентского Script Pad нельзя** — это не среда
  выполнения workflow-действий.

## 2. Что нельзя использовать в Script Pad

- Скрипты-действия бизнес-процессов вида
  `public void Execute(IActivity activity)` — им нужен объект `IActivity`,
  который предоставляет только движок процесса.
- Скрипты, завязанные на `ICSharpScriptContext ScriptContext`, переменные и
  атрибуты процесса (`activity.Variables`, `activity.Process`,
  `activity.Attachments`) — этих элементов в Script Pad нет.
- Ожидание, что клиентский Script Pad подменит сигнатуру входа. Сигнатура
  точки входа — контракт с хостом; несовпадение даёт
  `TargetParameterCountException`.

Правильные способы проверки такого скрипта:

1. Запуск в реальном процессе (тестовая копия базы), в той точке, где он
   навешан администратором (см. комментарий-шапку скрипта, строки 5–17).
2. Если нужен именно тест в Script Pad — писать **отдельную обёртку** под
   сигнатуру точки входа Script Pad. Точную сигнатуру следует снять с
   шаблона "Новый сценарий C#" конкретной версии IPS: в дистрибутиве шаблон
   встроен в DLL, отдельного файла-шаблона нет.

### Побочные эффекты скрипта (важно)

Скрипт пишет в БД: создаёт объект типа "Поручения", добавляет связь "Состав
канцелярского документа" и запускает процесс поручения (рассылку
исполнителям), если он настроен. Перед проверкой — тестовая копия базы и
нужные права (см. шапку скрипта, строки 8–17).

## 3. Как определить версию IPS

Отдельного REST-эндпоинта версии в `swagger.json` нет. Версия отдаётся
HTTP-заголовком `ips-version` на **любой** ответ сервера (включая 404 и
ответ аутентификации):

```
ips-version: 9.0.4.11310
```

Проверено против `http://192.168.80.70:8080`: заголовок присутствует на
корне, на `/core/api/Auth/authenticate`,
`/core/api/currentUsers/userInfo`, `/core/api/Bridge/GetPlugins` и даже на
404.

### Доступ из MCP

Добавлен read-only инструмент `ips_get_server_version`, возвращает:

```json
{ "baseUrl": "http://192.168.80.70:8080", "ipsVersion": "9.0.4.11310" }
```

## 4. Внесённые изменения в проект D:\IPS\IPS-MCP

| Файл | Изменение |
|---|---|
| `src/ips_mcp/ips.py` | `IpsClient` захватывает заголовок `ips-version` с любого ответа (`_capture_version`); добавлено свойство `base_url` |
| `src/ips_mcp/server.py` | новый read-only инструмент `ips_get_server_version` |
| `tests/test_ips.py` | тест `test_captures_ips_version_header` |
| `README.md` | инструмент добавлен в таблицу |

Проверка:

```
python tests/test_ips.py
```

Все тесты, включая новый, проходят.

## 5. Ограничения и что учесть

- Инструмент `ips_get_server_version` появится в клиенте только после
  **перезапуска OpenCode** (реестр MCP читается при старте).
- Версия читается с заголовка ответа, то есть требует хотя бы одного
  успешного обращения к IPS; инструмент сам делает дешёвый запрос
  `GET /core/api/currentUsers/userInfo`.
- Значение заголовка зависит от версии сервера IPS, а не от версии Web API
  из `swagger.json` (`info.version` там всегда `1.0` и для версии IPS не
  годится).

## 6. Ошибка исполнителя действия «Сценарий» (workflow)

Текст от системы при возврате шага:

```
Возвращено автоматически. При выполнении действия "Сценарий" произошла
ошибка: Исполнителем действия должен быть один исполнитель, найдено 0
шаблон процесса 1412434, индефикатор сценария 1412465
```

### Причина

Сообщение формирует workflow-движок **до** запуска тела скрипта. Для
действия типа «Сценарий» движку нужен ровно **один исполнитель** —
пользовательский контекст, от имени которого исполняется `activity.Session`.
Если на шаге исполнитель не задан (или источник разрешился в 0), действие
возвращается с этой ошибкой. C#-код при этом не выполняется.

Объекты: `1412434` — «Создание поручения test», тип 1133 «Шаблоны
процессов»; `1412465` — «...Сценарий 1», тип 1889 «Локальные сценарии
маршрутизатора», текст в атрибуте 1324 «Текст сценария».

### Решение (подтверждено)

Исполнитель шага «Сценарий» был указан неверно. В этом процессе надо
задавать источник **«Инициатор процесса»** (в шаблоне — attribute 1394,
пользователь `1238312`). Тогда исполнитель ровно один, и действие
запускается.

### Замечания

- Конфиг исполнителей шага через Web API не читается: у шаблона пустой
  `composition`, модель процесса хранится внутри. Настраивается только
  в конструкторе процессов.
- Сам скрипт дополнительно требует переменную «Технолог» и хотя бы одно
  вложение (`activity.Attachments`); при нарушении — `NotificationException`
  с другим текстом, а не ошибка исполнителя.
