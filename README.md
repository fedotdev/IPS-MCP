# IPS-MCP

MCP-сервер для безопасного **read-only** доступа к [IPS Web API](https://www.intermech.ru/) через модель Context Protocol (MCP).

Мост транслирует типизированные инструменты в вызовы IPS Web API, нормализует ответы для LLM
(ID → читаемые имена, убирает служебные поля) и не требует установки клиентского IPS SDK.

## Возможности

- 12 read-only инструментов по доменам: объекты, состав, связи, метаданные, ЖЦ.
- Авторизация через JWT с автоматическим refresh после `401` (без гонок, one-flight).
- Числовые ID типов/связей/атрибутов дополняются человекочитаемыми именами из справочника `gloss.db`.
- Дерево состава с ограничением глубины, числа узлов и защитой от циклов.
- Ошибки IPS возвращаются как читаемый текст (`IPS: объект не найден (id=42)`), без стек-трейсов.
- Без MCP SDK: минимальный JSON-RPC 2.0 сервер поверх stdio на стандартной библиотеке.

## Инструменты

| Домен | Инструмент |
|---|---|
| Сессия | `ips_get_current_user` |
| Объекты | `ips_get_object`, `ips_get_object_attributes` |
| Состав | `ips_get_composition`, `ips_get_composition_filtered`, `ips_get_composition_tree` |
| Связи | `ips_get_relation`, `ips_get_relation_attributes` |
| Метаданные | `ips_get_object_type`, `ips_get_attribute_type`, `ips_get_relation_type`, `ips_get_lifecycle` |

> Все инструменты read-only. Операции записи в этот релиз не включены намеренно.

## Требования

- Python 3.10+
- `httpx` (единственная зависимость)

## Установка

```bash
pip install -e .
```

## Конфигурация

Параметры задаются переменными окружения — секреты не хранятся в конфигурации и коде:

| Переменная | Обязательно | Описание |
|---|---|---|
| `IPS_LOGIN` | да | Имя пользователя IPS |
| `IPS_PASSWORD` | да | Пароль пользователя IPS |
| `IPS_BASE_URL` | нет | По умолчанию `http://192.168.80.70:8080` |
| `IPS_ROLE_ID` | нет | ID роли при входе (по умолчанию `0`) |
| `IPS_GLOSS_DB` | нет | Путь к `gloss.db` (по умолчанию `gloss/generated/gloss.db`) |

Пример:

```bash
export IPS_LOGIN=user_name
export IPS_PASSWORD=user_password
export IPS_ROLE_ID=782041
```

## Запуск

```bash
ips-mcp
```

Сервер читает MCP-запросы (JSON-RPC 2.0) из stdin построчно и отвечает в stdout —
стандартный транспорт MCP. Подключается как **stdio** MCP-сервер в любом MCP-клиенте.

Или напрямую:

```bash
python -m ips_mcp.server
```

## База знаний (gloss)

Имена типов, атрибутов и связей подтягиваются из `gloss.db` (SQLite), который генерируется
из Excel-выгрузок IPS администратором:

```bash
pip install openpyxl
python gloss/generate_gloss.py
```

Результат — `gloss/generated/gloss.db` + JSON-экспорт + манифест сборки. Файлы сборки
не хранятся в репозитории и воспроизводятся этой командой. Сервер работает и без
справочника — просто без подстановки имён.

## Тесты

```bash
python tests/test_ips.py
```

Проверяются: вход и refresh по `401`, маппинг ошибок, нормализация ответов — на
`httpx.MockTransport` без реального сервера.

```

├── generate_gloss.py   # генератор базы знаний из Excel

```

## Безопасность

- Сервер не выполняет операций записи — изменяющие endpoint'ы в контракт не включены.
- Токены IPS хранятся только в памяти и не попадают в ответы MCP и в логи.
- Пароль принимается из переменной окружения, не из аргументов и не из конфига.
- Права на операции остаются в IPS Web API; мост не дублирует бизнес-логику.

## Ограничения

- Справочник `gloss.db` привязан к конкретной базе IPS, ID нельзя переносить между базами
  без повторной выгрузки.
- Разворачивание `ftObjectLink` (числовая ссылка на объект) в читаемые поля пока не реализовано.
